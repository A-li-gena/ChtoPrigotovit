# ЧтоПриготовить 4.0

Android-приложение: регистрация → обязательный опрос → дневная норма → подбор блюд свайпами из того, что есть дома → готовка с голосовой озвучкой шагов.

## Запуск за 3 шага

1. Android Studio → **File → Open** → выбрать папку `ChtoPrigotovit/`.
2. Дождаться **Gradle Sync**.
3. **▶ Run 'app'**.

Ручных правок не нужно. Проект сам выбирает JDK 21 для Gradle (файл `gradle/gradle-daemon-jvm.properties`),
поэтому даже если на компьютере по умолчанию стоит JDK 25, сборка не должна запускаться на нём.
Если Android Studio всё же показывает "Incompatible Gradle JVM version" и JDK 25 — один раз выберите:
**Settings → Build, Execution, Deployment → Build Tools → Gradle → Gradle JDK → "Use Gradle Daemon JVM Criteria"**
(или встроенный JDK 21 / JBR Android Studio), затем Sync. JDK 25 для этого стека не поддерживается. Фотографии блюд лежат локально в `assets/`, интернет для них не нужен. Из разрешений — только уведомления (по вашему включению в профиле). Камеры нет.

## Как пользоваться

1. **Регистрация** (имя, e-mail, пароль). Гостевого режима нет.
2. **Опрос** (обязательный, без него на главный экран не попасть): пол, возраст, рост, вес, активность, цель, аллергии (чипы + своя строкой), любимые кухни, нелюбимые ингредиенты.
3. **Сегодня**: кольцо калорий, БЖУ, вода (+150/+250/+500), «сколько ещё можно съесть», кнопка «Подобрать блюдо».
4. **Корзина продуктов** → **свайп-лента**: влево «не это», вправо «в избранное», штамп-анимация одинаковая в обе стороны. В конце ленты: «Открыть список продуктов заново» (та же корзина, лента заново) и «Обновить продукты» (изменить набор).
5. **Рецепт**: порции ±, граммовки пересчитываются, предупреждение о вашем аллергене, «В дневник».
6. **Готовка по шагам**: крупный таймер, «Прочитать весь рецепт» / «Прочитать шаг».

## Нормы (считаются из ваших данных)

- Калории: Миффлин–Сан Жеор × активность (1.2 / 1.55 / 1.725) + цель (−400 / 0 / +300), минимум 1200 ккал.
- Белки 1.6 г/кг, жиры 0.8 г/кг, углеводы — остаток. Вода 30 мл/кг + 0/200/400 мл по активности.

Изменить данные: **Профиль → Изменить данные** — нормы пересчитаются сразу.

## Что убрано в 4.0

Гостевой режим; все предзаполненные данные (на старте корзина, дневник, вода, избранное и аллергии пустые); список покупок полностью; камера и распознавание по фото полностью (экраны, разрешения, зависимости); кнопка «Показать онбординг» в профиле; неработающая верхняя кнопка-«лист» — **удалена** (действия, которая она должна была делать, в продукте не осталось).

## Что важно знать

- **Голосовые команды** («дальше/назад/повтори/таймер 5 минут») **временно отключены**: распознавание речи на главном потоке давало микрофризы рядом с TTS. Управление — кнопками, озвучка шагов работает. Это осознанное отключение, а не баг.
- TTS: один движок на всё приложение (`Speak` в Application), ru-RU, скорость 0.95, `USAGE_MEDIA` (канал доступности на части устройств выкручен в ноль — голос терялся).
- Данные хранятся только на устройстве (DataStore). Удаление аккаунта в профиле очищает всё.
- Фото блюд: настоящие фотографии Unsplash вместо эмодзи (эмодзи-визуалов в интерфейсе не осталось). Один helper `ImageView.loadDishImage()` в `Ui.kt`: crossfade 150 мс, кэш памяти и диска, запрос под размер экрана, fallback — название блюда на нейтральном градиенте. Полный список фото с лицензиями — `docs/image-credits.md` в корне репозитория.
- Стек: Kotlin, View (без Compose), один ViewModel + Repo + DataStore, без Hilt и Room — сознательно минимум кода: 17 Kotlin-файлов, ~1980 строк.

## База блюд

**260 блюд**, хранятся локально в одном файле `data/Recipes.kt` (один источник правды, без сервера).
Категории: завтраки — 40, супы — 30, салаты — 30, горячее с мясом/птицей — 40, рыба и морепродукты — 25,
вегетарианское — 30, гарниры — 20, выпечка и десерты — 20, напитки — 15, соусы — 10.
Кухни: русская, итальянская, французская, средиземноморская, кавказская, среднеазиатская, индийская,
китайская, японская, тайская, мексиканская, американская, скандинавская, ближневосточная — у каждой 17+ блюд,
включая культурные вариации (омлет по-французски / тамагояки / тортилья, плов по-узбекски / по-азербайджански и т. д.).
У каждого блюда: категория, кухня, описание, ингредиенты с количествами, 4 шага с временем, общее и активное время,
сложность, порции, КБЖУ, аллергены, теги и фото. Целостность базы проверяет `RecipesTest`.

## Фотографии

У каждого блюда своя уникальная картинка, сгенерированная специально для приложения и лежащая локально: `app/src/main/assets/dishes/dish_{id}.jpg` — 260 разных изображений, отображаются мгновенно и без сети.
(кэш памяти и диска, crossfade, запрос под размер экрана, fallback — название на нейтральном фоне).
Полная таблица «блюдо → URL → автор → лицензия → источник» — `docs/image-credits.md` в корне репозитория.
Скачать фото в `assets/` в текущей среде нельзя (нет доступа к CDN), поэтому после первой загрузки
фото берётся из дискового кэша, а офлайн без кэша показывается fallback. Чтобы заменить фото блюда,
поменяйте `imageUrl` у блюда в `Recipes.kt` и строку в `docs/image-credits.md`.

## Как добавить блюдо

1. Откройте `data/Recipes.kt`, скопируйте любой блок `Recipe(...)`.
2. Дайте новый уникальный `id` и конкретное название (без дублей — это проверит тест).
3. Заполните ингредиенты через `ing("Продукт", количество, "г")` — название продукта из словаря `pantry` попадёт в свайп-подбор.
4. Укажите шаги, КБЖУ, аллергены, теги и `imageUrl` лицензионно чистого фото; добавьте строку в `docs/image-credits.md`.
5. Прогоните `./gradlew test` — `RecipesTest` проверит уникальность и полноту.

## Как изменить имя и фото профиля

Профиль → **«Изменить имя»** (диалог, сохраняется в DataStore) или **«Изменить фото»**
(системный выбор фото из галереи — разрешений не требует). Без фото показывается инициал имени
в нейтральном круге. Имя и фото сразу видны в профиле и в приветствии на экране «Сегодня».

## Проверка

`./gradlew assembleDebug` и `./gradlew test` (формулы норм покрыты юнит-тестами в `CalcTest`).
